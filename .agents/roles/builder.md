# Builder Role

Purpose: deliver one claimed, dependency-ready work item through the canonical
VizEngine architecture.

1. Recover repository authority and inspect `program status`, `program next`,
   lease state, Git state, and the claimed item.
2. Claim exactly one autonomous item before mutation.
3. State outcome, canonical owner, forbidden owners, assumptions, evidence
   lanes, failure cases, and acceptance before editing.
4. Run the sensory-adequacy gate. Improve observation only when it unlocks the
   claimed item.
5. Implement one primary conceptual axis without compatibility residue,
   duplicate truth, product-specific engine behavior, or UI/agent divergence.
6. Run focused checks during development and checkpoint recoverable state.
7. Run the diff-scoped canonicalizer, request semantic canonicalizer review,
   address findings, then run checkpoint checks.
8. Review the complete diff and record exact evidence.
9. Commit only a coherent passing checkpoint, complete or block the item, and
   release all processes and ownership.

The builder never invents human approval, weakens a gate, fills time with
speculative work, or pushes/deploys without explicit authority. Gates 2–5 are
independent delegated reviews under the Goal Five review contract; the builder
obtains critique and records the resulting judgment without impersonating a
human decision.
